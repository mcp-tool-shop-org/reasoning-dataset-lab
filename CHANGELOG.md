# Changelog

All notable changes to `reasoning-dataset-lab` are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Changed

- **Pilot A: the 12 floor and ceiling cells are buildable, on role-set d29499f.** `role-set` is re-pinned to `d29499f77a81bda144ebd51885f3c167a04667aa` (role-set #122; `pyproject.toml`, `uv.lock`, the adapter's `ROLE_SET_COMMIT`, the registry citation in `map.py`). The adapter no longer hard-codes the claim question: it reads the shortcut's `from` operator in role-set's `REGISTRY` and builds an exact (`=`) item with the claim question and a floor (`>=`) or ceiling (`<=`) item with the set question ("Which of them could be ...?"), because a claim cannot separate "at least k" from "exactly k" while the set of possible groups can. It filters the t10_variety catalogue by question, `ifs` and operator, and passes `target_shortcut` to `build_t10` for the set cells only; the exact cells keep the untargeted build, so their items and proofs are byte-identical to before (a pinned hash in the tests). A role-set without `target_shortcut` is refused when the generator is built (`ROLE_SET_PIN_LACKS_TARGET_SHORTCUT`). `examples/t10-pilot-a.map.yaml` now has 24 buildable cells (capacity 5 each) and no `role-set PR pending` cells; to keep its splits (train 48, eval 12) and shares, the 12 exact cells' targets are 3 (were 5) and the 12 new cells' targets are 2, total 60. The receipts of the exact cells name the new generator commit, which is the only field of theirs that changes.
- **certify-values: the licence-registry gate, a registry sha in the manifest, and a role fallback that refuses.** `rdlab pilot-b certify-values` now requires `--licence-registry <absolute path>` and, before any Ollama call, validates exactly the reader pins that will run against it, so a real certify-values run refuses (`PILOT_B_LICENCE_NOT_IN_REGISTRY`) when rnd's registry lacks a reader's licence entry (until now only `rdlab models --verify-live` did). The manifest records `licence_registry_sha256`, and `verify_manifest` requires it; `rdlab pilot-b verify-values-manifest --licence-registry <path>` recomputes it from the file. `OllamaBlindReaderAdapter` built without a role now maps the model family to its role (nemotron to reader_1, granite to reader_2, mistral to reader_3) and refuses any other family with `PILOT_B_UNKNOWN_READER_FAMILY`, instead of defaulting to reader_1. Earlier manifests carry no registry sha and no longer verify.

- **reader_3: Mistral Small 3.2 24B (Apache-2.0) as the c2 second-reader family; no run yet.** `DEFAULT_PILOT_B_MODEL_PINS` gains `reader_3` (`mistral-small3.2:24b`, manifest digest `5a408ab5...`), `rdlab pilot-b certify-values --readers` accepts `mistral`, and the manifest verifier allows a reader_3 that ran. A manifest made by the other two readers still verifies. The licence registry needs the entry `mistral-small-3.2-24b-hf-card`, so a real (non-stub) run refuses until rnd's registry carries it.

- **control pairs v2: six arguable pairs replaced; earlier control results don't carry over.** A control pair must be compatible beyond argument, so the six whose key a careful reader could rightly dispute (chromoly then ferritic steel, a carbide coating then ceramic, docked then moored, sealed then waterproof, acoustic then sonic, a dry gas seal then mechanical seal) are replaced by chromoly then alloy steel, an alumina coating then ceramic, a steel hull then metal, IP67 then dust-tight, R-134a then HFC-134a, and a silicon-carbide seal face then ceramic. The other fourteen, the 0.80 threshold and the pass rule are unchanged. The manifest records `control_pairs_sha256`, and `verify_manifest` recomputes it, so a manifest made under the old table fails verification.

- **certification asks its own question.** The first full run showed the triad blind-read prompt (does the claim follow from the material?) makes a reader answer "unsupported" to a compatible but unstated claim (ester then synthetic), so it cannot tell a contradiction from a gap. `rdlab pilot-b certify-values` now asks: "Statement 1: The <attribute> of <entity> is <v1>. Statement 2: ... Could both statements be true of the same <entity> at the same time?", answered with exactly one word, `compatible` / `incompatible` / `unsure`, parsed strictly (case and surrounding whitespace ignored; anything else is a parse error and counts toward the error stop). A pair is a contradiction only on `incompatible`; a control pair passes on `compatible` or `unsure`. The 20 control pairs are unchanged. Same pins, `think` on, `num_predict` 3072, `num_ctx` 4096. The manifest records the sha256 of the prompt text, and `verify_manifest` rejects a manifest made with any other prompt. `verify_manifest` also recomputes each reader's control passes from the pairs and enforces the 0.80 threshold itself, instead of trusting the recorded `passed`. The real reader adapter gains `chat_raw` for callers that build their own messages. The CLI no longer writes the manifest a second time.

- **generator: every categorical value set sits on one axis and its values exclude each other.** An unsupported claim swaps the true value for another from the same set, so it is a contradiction only if both cannot be true. An audit of all 50 value sets (10 domains x 5) found most of them mixed an axis (a material beside a type, a mode beside a sub-process) or held a class beside its member (`synthetic` beside `ester`, `mineral` beside `paraffinic`, `air` beside `nitrogen`, `grounded` in two transformer sets), which makes an `unsupported` claim true and its key wrong (Pilot B stub 10d). All 50 sets were rewritten as 5 values on one declared axis (`VALUE_SET_AXES`); the 10 state sets hold top-level operating modes only, and no value sits in two sets of a domain. Some attribute names changed with their axis (for example `grid status` is now `turbine mode`, `valve state` is `pump state`), so facts and tables generated from a seed differ from earlier builds. `VALUE_SUBSUMPTIONS` records the known overlaps as a regression lint, `EXCLUSIVE_BY_MEANING` the close pairs reviewed with a reason, and `tests/test_pilot_b_value_sets.py` fails on a covering value beside its member, on one value spelled inside another, and on a value in two sets of a domain.
- **The exclusivity guard is not enforced yet.** The lint above only catches overlaps someone has written down; new or replacement values get no protection from it. The enforcing guard is the certification below, and it does not switch on until the certification PR (the manifest from a real run on the readers, `is_disjoint_value` reading it, and a CI gate that every set is certified with a matching hash). Until then, do not read this change as protection it does not give.
- **value certification tooling, with no certification claimed.** `pilot_b/value_certification.py`: `rdlab pilot-b certify-values` asks two local reader families whether every directed pair in a set (20 for 5 values) reads as a contradiction, one reader loaded at a time, with `--num-ctx`, `--num-predict`, `--readers`, a calibration of the first calls that stops the run when the projected time passes `--wall-cap-s`, and an error-rate stop (`--error-rate-stop`, 2% by default). It writes a content-hashed manifest of the admitted sets and a review queue of the others. `rdlab pilot-b verify-values-manifest` loads a manifest and fails when any set is uncertified or its hash no longer matches. Tested with fake readers; no manifest is committed.
- **certification: provenance, partial results, unload.** `verify_manifest` now requires a complete run, at least two readers from distinct families whose name, digest and family equal the pinned reader models in `DEFAULT_PILOT_B_MODEL_PINS` (a fake reader cannot match), and verdict keys equal to the manifest's reader names. A run that stops (error rate, wall cap) writes its manifest marked `"complete": false` with the stop code, the review queue, and `<queue>.failures.jsonl` (reader, pair, done_reason, completion_tokens, the tail of the raw text, or the error code); every exit path unloads the reader it loaded; the calibration projection also runs when one reader's jobs equal `--calibration-calls`. Defaults `--num-predict 3072`, `--num-ctx 4096` (thinking tokens count against `num_predict`; measured up to 2,019 in stub 10d); `--num-ctx` is a cap.
- **certification: length routing and a negative control.** A `length` or `max_num_ctx_exceeded` stop means not certified: the pair goes to the review queue with its reason and the failing call is logged, but it does not count toward `--error-rate-stop`, which counts only transport and parse errors. Before its certification calls each reader answers 20 compatible pairs (a member then its class, a synonym, an implication) through the same prompt and settings; it passes with at least 16 of 20 answers that are not "unsupported" (`--control-pass-threshold`, default 0.80; length stops and errors fail). If a reader fails, the run certifies nothing: the manifest says `"control_failed": true`, every set goes to the review queue, and the reader is unloaded. `manifest["control"]` records each reader's passes, threshold and every pair's verdict, done_reason and tokens, and `verify_manifest` rejects a manifest with no passing control.
- **reports record the render-failure gate.** `pilot_b_report.json` carries `render_failure_rate` and `max_render_failure_rate` (schema updated).
- Four more sets re-cut after the Argon review: reactors/cladding metal, compressors/rotor coating, boilers/tube alloy, chillers/condenser cooling (they need re-certifying).
- **render: the value-before-entity check is dropped, and intervals may be written two ways.** One entity per sentence already stops a value binding to the wrong entity. An interval may be "between <lo> and <hi>" or "from <lo> to <hi>". The writer prompts ask for "between" and for a direct verb (is, operates in, uses, has) on exact facts, never a hedged link such as "characterized by" or "associated with".
- **gate: render failures are their own rate.** They no longer count against every verdict class: class rates are over the triads that rendered, and `max_render_failure_rate` (default 0.50) halts the build with `PILOT_B_RENDER_FAILURE_RATE_ABOVE_CEILING`.
- **`mutate_fact_value` refuses instead of falling back.** A value outside its own attribute's set raises `PILOT_B_NO_EXCLUSIVE_VALUE`; the cross-attribute swap and the `non-<v>` / `uncoated-<v>` strings are gone.

- **Python: `requires-python` is `>=3.13` (was `>=3.12,<3.13`); Python 3.12 is dropped.** 3.15 is the main target (`.python-version`); CI runs the suite on 3.15 (`test`, with the Atlas check), 3.13 (`test-py313`) and 3.14 (`test-py314`), each from `uv sync --frozen`. Coverage (floor 90) and a Codecov upload run on the 3.15 leg only; the 3.13 and 3.14 legs run the tests without coverage. Every action is pinned by commit SHA with a version comment, at its current major (checkout v7.0.1, setup-uv v10.3.2, setup-node v7.1.0, codecov-action v7.1.1, read 2026-10-25). `role-set` is re-pinned to its commit that supports `>=3.13` (`d105f3d`, role-set PR #121; to be re-pointed to the merge commit). The Part F parity test now expects `>=3.13`. On 3.15, PyYAML 6.0.3 installs from its source distribution until it publishes cp315 wheels.

- sealing: the per-build seed is kept in the sealed store.
- sealing: the render inputs are validated at write and at verify, the report is cross-checked against them, and the schema maps are closed.
- sealing: more render-input rules (unique digests, constant call fields, catalogue domains, regular whitespace) and a coverage check on the report.
- sealing: the writer's whitespace is regularised before anything reads it, each call's model must be the recorded one, and the report's coverage numbers must add up.
- generator: per-build secret variation in table values and homogeneous triad surface features; variety: surface-feature balance and triad-level assignment baseline checks.

## [0.3.0] - 2026-10-25

### Added

- Pilot B builder (`reasoning_dataset_lab.pilot_b`):
  - **Part A (`fact_tables.py`):** Typed atomic fact tables (`number`, `date`, `interval`, `state`, `attribute`) with `closure` tags (`open` or `closed`), contrast triad construction (`supported`, `unsupported`, `cannot_tell`), and code-proved keys (`fact_restatement`, `disjoint_mutation`, `interval_interior_refinement`, `open_excerpt_unmentioned_attribute`).
  - **Part B (`rendering.py`):** Writer adapter protocol, deterministic writer and adversarial fakes (`FlippedBoundWriterFake`, `RelationalSwapWriterFake`, `UnlistedNumberWriterFake`, `UnlistedProperNounWriterFake`), sentence-level fact binding, polarity and quantifier direction checks (`at least` vs `at most`, negation, `only`, `between`), ungrounded number/proper-noun refusals, and structural token whitelisting (`DESIGN.md` ruling 8a, §11 step 3, §2.4).
  - **Part C (`unanimity.py`):** Blind-reader adapter protocol, key-free blind-read prompts, two-family unanimity gate, whole-triad pass/fail routing to `review_queue.jsonl`, hard refusal on same-family self-verification, reader family collision, Muse-Glimmer, and Argon/Gemini, and `min_pass_rate_per_class: 0.50` build halt (`DESIGN.md` ruling 2, ruling 8c, §6).
  - **Part D (`waves_and_sealing.py`):** Single-model wave runner (`render`, `word`, `reader_1`, `reader_2`) enforcing non-interleaved wave execution and per-call thinking token caps (`ruling 8b`), seeded item shuffling, aggregate-only judgment provenance (`§2.1`), external `keys.sealed.jsonl`, and content-based plus field-name sealing verification (`ruling 5a`).
  - **Part E (`models_and_build.py`, `ollama.py`, and CLI):** Pinned Ollama tags and manifest/layer digests for `qwen3.6:35b`, `nemotron-3.5-lightning:30b`, and `granite4.2:8b` with configurable `licence_id` checked against `licences/registry.json`, real loopback Ollama writer and blind-reader adapters (`OllamaWriterAdapter`, `OllamaBlindReaderAdapter`, interlock #140 loopback guard, pre-call `/api/tags` digest check with no auto-pull, per-wave `keep_alive: 0` model unload, and `is_fake` sealing guard), `rdlab models --verify-live`, `rdlab pilot-b --stub N`, and the Pilot B build report (`coverage`, `key_proof_rate: 1.0`, `gate_pass_rate_per_class`, per-wave timing/tokens, 50-triad full-build estimate, and 20-item human sample).

### Changed

- **Part F (`pyproject.toml`):** Narrow `requires-python` to `">=3.12,<3.13"` to match `role-set` at its pinned commit `2b26840`, with a regression test verifying that the lab never allows a Python version that `role-set` refuses.

## [0.1.0] - 2026-10-24

### Added

- Package scaffold (`src/reasoning_dataset_lab/`) for Python 3.12 with the `rdlab` CLI entry point.
- `map.yaml` schema validator and canonical map SHA-256 computation (`reasoning_dataset_lab.map` and `rdlab map check`), enforcing cell `target`, `capacity`, and `reason` (required when `capacity == 0`), share floors and ceilings, variety caps, `acceptance` rules (`min_pass_rate_per_class`, and `unanimity_rate` restricted to `judged` kinds), unknown-key refusals, and structured `{code, message, hint}` errors with exit codes `0` (clean), `1` (refused), and `2` (usage).
- Example map `examples/t10-pilot-a.map.yaml` covering T10's full intended 24-cell map across all four `role-set` shortcut-registry wrong families (`exact_read_as_floor`, `exact_read_as_ceiling`, `floor_read_as_exact`, `ceiling_read_as_exact`), with 12 buildable cells summing to 60 items and 12 floor/ceiling cells at `capacity: 0, reason: "role-set PR pending"`.
- Minimal loaders for the five project files (`project.json`, `constitution.json`, `terminology.json`, `lanes.json` derived from the map's `kind` axis, and `rubric.json`) and deterministic config fingerprint (`rdlab project fingerprint`) covering the five files, the map, and canon in fixed order.
